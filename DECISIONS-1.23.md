# Decisions: 1.22.0 finish and 1.23.0 (made without asking; the safer, simpler option)

1. **Preflight skipped** (owner's request); 1.21.1 was already published, so Phase 1 starts at 1.22.0.
2. **Tests are gentle on the Mac** (3 WindowServer watchdog panics on 4 Nov 2026):
   - At most 2 test workers (`WORKERS`, `LF_TEST_WORKERS` overrides); builds with `-j 4` when `LF_BUILD_JOBS` is set. (Tightened in 8.)
   - Every class that puts a real window on screen or records it runs alone, one class at a time with a 3 s pause (`UI` joins `SERIAL`; `SCREEN_SNAPSHOTS` in test-full).
   - A load guard (`guarded` in scripts/test-groups.sh): every 10 s, WindowServer CPU and memory pressure; above 80 % for 30 s or critical pressure → stop, log to .build/test-guard.log, wait 2 min, clean up, run that part again (3 tries). (Replaced in 8: no automatic rerun.)
   - `cleanup_tests` after every run: xctest, the testing helper, the MCP helper, and any LF Studios copy outside /Applications.
3. ~~Screenshot tests offscreen~~ (replaced by 9 and 10: the change is stashed, not applied).
4. **Synthetic test events are not slowed down**: they are handed straight to views inside the test process and never go through WindowServer, so pacing them wouldn't lower its load; fewer windows does. New tests that post real system events (Phase 2) go through one paced helper.
5. **Login / crash recovery**: checked; LF Studios never reopens a project by itself. An interrupted recording only shows a toast ("Click to open it"), no window is restorable, and drafts aren't opened at launch. No change needed.
6. **One test-quick per batch, not per commit**: each heavy run risks the Mac, so a batch of commits is checked by one test-quick on their combined tree before pushing; the commits stay one change each.
7. **The crash was a test-helper leak, not the app** (found 5 Nov 09:56): `VideoTestSupport.writeFakeRecording` retried with `for _ in 0..<500 where CVPixelBufferPoolCreatePixelBuffer(...) != success`, which calls Create on every pass and leaks each buffer it overwrites (499 a frame, ~5 MB each at 1440×900). The editor screenshot test reached 7.8 GB in 2 s; swap filled and WindowServer stopped answering. Fixed to stop at the first buffer; TestMediaMemoryTests guards it (small frames, so a relapse can't hurt the Mac).
8. **Rules from 5 Nov 22:27** (scripts/test-groups.sh): 1 test worker, `swift build -j 2`; critical memory pressure, WindowServer at >80 % for 30 s, or WindowServer not answering its window list within 5 s twice in a row stops the run, closes every test process and does not rerun that part, then waits for 2 calm minutes; warning pressure pauses before each part. Every screenshot/UI class runs alone under the 1.5 GB / swap +500 MB kill-switch.
9. **Screenshot windows**: each helper releases its window and the editor in it right after the picture (`defer`), instead of keeping all of them until the test ends; at most one editor is alive at a time.
10. **Offscreen snapshot stash not applied for now**: the leak, not on-screen windows, was the cause, and the stashed offscreen change is unproven against the 1.21.1 pictures. Kept in `git stash` for a later check (NEXT-RUN.md).
11. **Reference1211SnapshotTests made independent of what ran before**: the editor's tips page (a counter that moves on with every editor opened) is pinned to the pages 1.21.1's pictures show, and Recording ▸ Storage counts a test-owned 270 KB exports folder instead of the shared temporary one.
12. **Tests never read the real Desktop**: in a test process (XCTest loaded, the same check VideoDemoStores and VideoAIKeys already use) `Settings.defaultAutoSaveLocation` is a temporary folder. Home and the recordings list scan it, and a test reading ~/Desktop waits forever on a privacy prompt (AppearanceSnapshotTests 44 min, SettingsTests 34 min). The app is unchanged.
13. **Stuck tests**: the guard quits a test process that has used no CPU for 3 minutes, saving its stack to .build/test-stuck-*.txt; only that process goes, the run continues.
14. **VideoEditor115SnapshotTests stopped after 53 min** (memory-safe, just slow): left for NEXT-RUN.md instead of spending the audit's time on it.
15. **Performance tests use 1080p media and the preview test has a class of its own**: the export test's 2880×1800 60 fps fake recording broke the 1080p rule, and the export holds ~650 MB of caches for a while after it ends (no growth across exports: 4 small exports stay at 60 MB), so the export and preview tests together passed the 1.5 GB kill-switch. Each class runs in its own process; split, each stays under 1 GB.
16. **Audit fixes from reading the code** (AUDIT-1.23.md C1–R2): each finding was checked against its callers before fixing; the two that need two displays or exact timing (R1, R2) and the field identity (C4) are hand checks, not tests.
17. **Reference picture tolerance 4 → 12** (Reference1211Tests): exporting the same 1.13 "edited" project 5 times gave 4 identical to the reference and 1 that differed everywhere by 2–4 and by 9 on a dark fade-in frame: the hardware encoder's run-to-run noise, not a change in the app (it failed about 1 run in 3). A real change (a moved title, another colour) differs by tens.
18. **test-full stopped by hand at 15:46**: the owner's SRT Generator app (python, 10 GB) pushed swap from 1 GB to 8.9 GB; the kill-switch stopped two screenshot classes whose own memory was 22–25 MB. Continuing would only have stopped every class and added load, so the run was ended, the test processes closed, and the next run waits until swap stops growing and pressure has been normal for 2 minutes. The owner's app was left alone.
